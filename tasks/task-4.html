Task 4: Fine-Tuning Isolation Forest

If you haven't started your baseline yet, do that first. If you already have one, start playing with the parameters.

Key Points

Catch up

If you didn't get to Part 2 of Task 3, start there first: fit the baseline IsolationForest with default parameters, plot the anomaly score distribution, and pull out the 10 most anomalous transactions. Everything below builds on that baseline.

Parameters

scikit-learn's IsolationForest has a handful of parameters worth understanding before you tune them: n_estimators (number of trees in the ensemble, default 100), max_samples (how many rows each tree is built from, default "auto", which is min(256, n_samples)), contamination (the expected proportion of outliers, used to set the score threshold, default "auto"), and max_features (how many columns each tree considers, default 1.0, meaning all of them).

Assignment 4: Fine-Tune and Compare

Using the same baseline from Task 3, change one parameter at a time and see what actually moves:

  • contamination: try a few values (e.g. 0.01, 0.02, roughly the true fraud rate around 0.035, 0.05, 0.1). This mostly changes the decision threshold, not the underlying scores, so watch how the flagged set grows or shrinks rather than expecting the ranking to change.
  • n_estimators: try fewer and more trees (e.g. 50, 100, 200, 500). Does the anomaly ranking stabilize as you add more, or does it keep shifting? Is there a point past which more trees stop changing much?
  • max_samples: try the default, plus a few other sizes (e.g. 128, 512, or the full training set). Watch both the results and the runtime, this is usually the biggest runtime lever.

Write up what you find: which parameter had the biggest effect on your results? Did any setting noticeably change how many of your top-flagged transactions were actually fraud, once you peek at the labels? Were there trade-offs between runtime and anything improving?
