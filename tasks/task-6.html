Task 6: Fine-Tuning Local Outlier Factor

Same idea as Task 4: change one LOF parameter at a time and see what actually moves.

Key Points

Catch up

If you haven't finished Task 5's baseline yet, start there: fit the default-parameter LocalOutlierFactor on a 20,000-30,000 row subsample, plot the score distribution, and sanity-check against labels across the top 10 and top 3.5%. Everything below builds on that baseline.

Parameters

scikit-learn's LocalOutlierFactor has a few parameters worth understanding before you tune them: n_neighbors (how many neighbors define a point's local density, default 20), contamination (the expected proportion of outliers, used to set the score threshold, default "auto"), and metric (how distance is measured, default "minkowski" with p=2, i.e. ordinary Euclidean distance). There's also algorithm, which picks how neighbors get found, but with 401 features the tree-based options (ball_tree, kd_tree) stop helping and scikit-learn effectively falls back to brute-force distance computation anyway, so it's not a lever worth tuning here.

Assignment 6: Fine-Tune and Compare

Using the same subsample from Task 5, change one parameter at a time and see what actually moves:

  • n_neighbors: try a few values (e.g. 5, 20, 50, 100). A small neighborhood makes the score sensitive to very local structure and noisier, a large one smooths it out and makes LOF behave more like a global method. Does the top-flagged set hold steady as you move this, or does it shuffle a lot?
  • contamination: try the same values as Task 4 (e.g. 0.01, 0.02, roughly the true fraud rate around 0.035, 0.05, 0.1). Like in Isolation Forest, this mostly resets the decision threshold rather than the underlying ranking.
  • Subsample size: try a couple of sizes beyond your Task 5 baseline (e.g. 10,000 vs 30,000 vs 50,000 rows). Watch runtime closely, this is the biggest runtime lever for LOF, same role max_samples played for Isolation Forest, but it costs you a lot more here because of the ~O(n²) distance computation.

Write up what you find: which parameter had the biggest effect on your results? Did any setting noticeably change how many of your top-flagged transactions were actually fraud, once you peek at the labels? How does the runtime/quality trade-off here compare to what you saw fine-tuning Isolation Forest in Task 4?
